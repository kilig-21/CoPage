# CoPage 公司协同知识平台背景与阶段规划

记录日期：2026-10-08

## 一、产品背景与定位

CoPage 的长期目标是“协同知识库＋统一知识服务”。当前正在建设和完善的在线协同文档，是知识生产与维护的基础；后续在这套基础上增加公司知识组织、RAG 检索、站内智能助手和对外知识服务。

员工把制度、操作流程、产品资料、会议结论和实践经验放入平台，通过多人在线编辑持续纠错、补充和更新。平台将适合使用的已发布资料转成可检索知识，让员工、平台助手及其他业务系统使用同一套有来源、受权限约束的资料。

核心价值在于“共同维护一次，多处持续使用”：知识不只上传后静态存放，而是在实际问答和使用中不断被发现问题、修正并积累。外部系统不必反复复制文档或各自维护一份不同的知识库。

## 二、用户期望的使用过程

1. 员工创建或导入文档，在原在线编辑器中协作维护。
2. 根据资料用途加入个人、团队或公司知识集合，并设置阅读、维护与发布权限。
3. 需要成为回答依据的内容发布为明确版本，后台异步构建知识索引。
4. 员工在平台中向智能助手提问，答案展示实际来源，可回到同版本原文核查。
5. 客服、内部工作台或其他智能体通过统一接口获取答案或知识片段。
6. 发现回答错误或资料过期时，反馈给维护者；大家共同修正文档、重新发布。
7. 新发布知识生效后，站内与外部使用方共享更新结果；有价值的新经验经人工确认后沉淀为知识。

## 三、系统职责

| 部分 | 职责 | 主要实现位置 |
| --- | --- | --- |
| 协同文档工作台 | 编写、多人修改、历史恢复、文档权限 | 现有前端编辑器和后端文档/协同模块 |
| 公司知识管理 | 集合、成员、维护责任、发布版本、生命周期 | 前后端共同新增 |
| 知识处理管道 | 抽取、分块、embedding、索引与更新 | 主要在后端异步执行 |
| 知识检索服务 | 按当前授权范围寻找资料，返回实际来源 | 后端独立服务 |
| 平台智能助手 | 根据检索资料组织回答、会话与来源展示 | 后端编排/模型调用＋前端问答界面 |
| 对外知识服务 | 受控调用应用通过 API 取得答案或片段 | 后端服务和调用应用管理 |
| 反馈与运营 | 发现问题、协作修正、质量评测和维护 | 前后端及试点维护流程 |

RAG 是“检索资料，再依据资料生成回答”的方式；它不等于把公司文档训练进大模型。embedding 用于文字相似性检索，生成模型用于组织答案，二者分别配置。智能助手可以先交付知识问答，之后再按实际需求增加工具，不必先建设复杂多智能体框架。

## 四、当前基础与拟议能力

当前仓库已有在线富文本编辑、OT/WebSocket 协作、MySQL 正文与版本、文档成员权限、历史版本、回收站、Elasticsearch 全文检索及 MinIO 图片存储。Redis 和 RabbitMQ 已承担现有协同协调及后台处理相关职责，后续可以评估复用。

现有 ES 索引是全文检索副本，尚未具备本路线所述分块、向量和生成能力。公司组织/知识集合、知识发布、站内问答、对外知识 API 和反馈闭环均为后续阶段目标，不能当作当前已实现能力。

既有 [RAG 演进边界](RAG演进边界.md) 说明数据、权限和版本约束；CODI-93 已完成的是预留和边界验收。本文补充产品目标与阶段路线，不修改历史验收结论，也不自动启动 AI 功能。

## 五、贯穿各阶段的原则

- MySQL 中的业务正文、发布快照、当前权限和知识状态是事实来源；搜索/向量索引可重建，不能直接授予权限。
- 在线编辑 revision、知识发布标识和索引构建代次分别表达不同状态，必须关联；未保存草稿和旧操作历史不自动混入当前知识。
- 首期采用当前有效发布与索引匹配的策略。新发布索引未就绪时明确显示更新中，不能悄悄用旧内容冒充最新资料。
- 文档/集合权限如何组合需要明确建模；撤权、撤回或删除先影响授权，不依赖异步索引清理完成。
- 来源指向不可变发布版本，可定位实际片段；查看最新正文时提示版本变化，读取来源时重新校验权限。
- 资料不足时明确说明，冲突资料展示差异；模型答案经人工确认后才可沉淀为新的公司知识。
- 智能体与外部应用使用统一检索服务。外部应用的知识范围与员工权限组合校验，内部资料不能因 API 接入变成公开资料。
- 文档和检索内容是证据，不是系统指令。模型/索引故障不能阻断原有协同文档功能。
- 模型、部署方式、数据出口、分块参数、向量存储和评测目标在实施子任务时确定；这份规划不表示允许把实际敏感公司资料发送给第三方。
- 首期面向一个公司，提供清晰组织边界；多公司 SaaS、SSO、PDF/Word/OCR、爬虫和业务写操作另行按需要扩展。

## 六、阶段划分与管理方式

现有文档编辑作为基础阶段，不重复创建实现 issue。新增六个知识平台阶段，标题使用“知识平台阶段一｜……”等格式，与原有“01｜……”任务区分。

每个阶段 issue 是后续子任务的父级容器，具有目标、依赖、范围、交付物、验收标准和拆分方向。阶段可以分批交付；后续只有达到该阶段验收条件，才标记完成。本次仅编写规划和创建阶段 issue，不创建子任务，不启动智能体执行。

全部 issue 归属 Multica「共页（CoPage）」项目，负责人为 kilig lee，初始状态为 Backlog。既有 CODI-81～CODI-93 与 CODI-94 不作修改。

| --- | --- | --- | --- |

| 阶段六 | 反馈修正、知识沉淀与公司试点闭环 | 反馈依赖阶段四；外部闭环依赖阶段五 | CODI-107 |

## 七、阶段 issue 详细规划

以下内容与首次创建的 Multica issue 描述一致，方便后续拆分子任务。以后任务有调整，应同步维护路线说明；实时状态以 Multica 和实际验收证据为准。

### 知识平台阶段一｜建立公司知识库、成员权限与知识发布机制

#### 阶段目标与用户价值
把当前个人/协作型文档组织成可共同维护的公司知识库。员工能区分个人资料、团队资料和公司资料，明确哪些内容可以成为问答依据。协同编辑继续负责生产知识，知识发布负责确定可使用的版本。

#### 前置依赖与当前基线
承接现有文档编辑、成员权限、历史版本与回收站；这些功能已有实现，应复用并核查，不重新建设。已有 CODI-93 只完成 RAG 数据预留与边界说明，不代表知识问答已完成。首期服务一个公司，保留清晰组织边界；多公司 SaaS 不作为本阶段必做项。

#### 需要覆盖的工作
- 建立公司/团队、成员、知识库或知识集合与文档归属的最小模型；同一文档加入多个集合时，明确唯一内容来源，避免复制形成不同事实。
- 设计知识库首页、列表、分类与文档加入/移出入口；员工仍在原编辑器维护正文。
- 定义知识维护、发布、阅读和管理权限，明确集合权限与既有文档权限如何组合。个人文档不能因加入集合默认向全员开放；成员退出或撤权后立即停止读取。
- 分离编辑中的文档版本与可供检索的已发布版本。制度等资料支持显式发布；是否提供自动发布由集合配置决定，不强制增加所有文档的审批流程。
- 发布版本保存不可变正文快照与元数据，至少包含文档、编辑版本、发布标识、发布人、发布时间。未确认浏览器草稿、操作日志与普通历史版本不自动进入知识库。
- 明确发布、更新、撤回、删除、恢复、归档及并发发布规则。知识是否仍有效以业务状态和当前权限为准，不能等待异步索引清理才禁止访问。
- 给每个知识库/重要文档设置维护责任人，建立最小变更记录；回滚发布内容不倒退协同编辑 revision。

#### 阶段交付物
知识组织与权限说明、发布生命周期说明、数据/迁移设计、知识库管理界面及接口契约，为阶段二提供明确的已发布内容来源。

#### 验收标准
- 两位员工能共同编辑同一文档；读者和发布者按权限分别执行允许的操作。
- 私人、受限团队和公司共享知识的读取边界可实际验证；撤权/删除后正文与发布内容均不可越权读取。
- 修改草稿不悄悄改变已发布知识；发布记录可追溯到实际正文快照，撤回后不得作为回答依据。
- 已有文档、成员权限、历史、回收站和协同编辑经过针对性回归；空集合与无权限状态可理解。
- 完成可用于阶段二的固定资料集，覆盖发布、更新、撤回与受限访问。

#### 后续子任务拆分方向
组织/集合模型；权限组合与迁移；文档归属界面；发布快照及状态；生命周期事件；权限与协作验收。

#### 本阶段边界
不接模型、不计算向量、不开发聊天窗口；SSO、复杂部门树和完整审批工作流另行按实际需求确定。

#### 项目与执行约定
- 项目：共页（CoPage）；仓库：https://github.com/kilig-21/CoPage 。
- 产品定位：协同知识库＋统一知识服务。员工共同编写和修正文档，平台助手与外部系统使用同一套经过授权的知识。
- 本 issue 是阶段容器，后续由负责人拆分子任务；本次只建立规划，不启动实施、不自动创建子任务。
- 负责人：kilig lee。沿用当前 Java/Spring Boot、React/Quill 与 MySQL 等基础，执行前核实源码、分支、项目文档和已完成项。
- 保持现有在线编辑、OT/WebSocket、草稿恢复与权限功能可用；AI 或索引故障不能阻断正常编辑。
- 接口、迁移、事件和模型配置在子任务设计时具体确定；交付包含文档、可复现检查与实际验收证据，区分模拟验证与真实模型调用。
- 文档或检索内容不能改变系统权限或成为智能体指令；真实凭据和完整敏感正文不进入普通日志。

### 知识平台阶段二｜建设已发布文档的分块、向量索引与异步更新管道

#### 阶段目标与用户价值
让已发布知识自动变成可检索的片段，并随内容与状态更新。员工维护文档，后台完成知识处理，避免人工重复上传或每次输入都调用模型。

#### 前置依赖
依赖阶段一明确的集合、权限、发布快照和生命周期事件。先落实允许处理的数据范围、embedding 模型部署方式及外部服务的数据出口；本阶段规划不表示已经授权发送实际公司资料。

#### 需要覆盖的工作
- 从已发布 Quill Delta 快照抽取文字，保留可用于分块的标题/段落结构；排除图片地址、格式控制和未保存草稿。已有 SearchIndex 的文本提取可复用，但需增加结构与定位能力。
- 按章节/段落切分，定义长度、重叠和超长段落策略；记录集合、文档、发布标识、原文 revision、分块序号、正文、位置和内容哈希。
- 抽象 embedding 调用，记录提供方、模型版本、向量维度、分块策略版本。更换模型或策略时能够重新构建，不能混用不兼容向量。
- 优先评估复用现有 Elasticsearch 创建独立知识片段索引；选择其他向量存储必须说明收益、维护成本与迁移方式，不预先强制增加数据库。
- 利用现有 RabbitMQ/后台处理能力，在已提交业务变更后异步构建；合并重复事件，按内容哈希复用可复用结果，限制批量大小与并发。
- 建立待处理、处理中、就绪、失败、已失效等可观察状态；支持幂等处理、退避重试、人工重试、遗漏事件巡检和全量重建。
- 以发布标识/构建代次隔离任务。重复消息、任务乱序、构建期间再次发布或删除时，旧任务不得覆盖新状态或复活旧知识。
- 新发布尚未就绪时明确展示更新中；检索只使用与当前有效发布匹配的完整索引代次。首期不静默退回旧发布内容。
- 删除、撤回和撤权立即作用于业务授权；索引异步清理有状态与重试，索引不是最终知识状态或权限来源。
- 提供索引状态、失败原因和管理员重建入口；密钥管理、调用预算、超时和日志脱敏纳入处理管道。

#### 阶段交付物
可重建的知识片段索引、后台任务与状态模型、事件契约、模型/存储配置说明、重试与重建操作说明。

#### 验收标准
- 发布中文、标题、多段落、长段落与含图片的文档后能得到合理片段，能定位同版本原文且不包含图片 URL。
- 重复投递不产生重复有效片段；旧任务晚完成不会覆盖新发布，撤回/删除途中不会复活知识。
- embedding/索引暂时故障后可恢复或重试，现有在线编辑仍正常。
- 全量重建保持业务正文与权限不变；维度/模型配置不兼容时显式失败或按设计重建。
- 展示并验证更新中、失败、就绪状态；真实模型验收与可替换模型测试分别记录。

#### 后续子任务拆分方向

### 知识平台阶段三｜建立权限感知的知识检索、来源定位与质量评测

#### 阶段目标与用户价值
形成可复用的知识检索能力：针对问题找到有权限、仍有效且相关的资料，返回可以核查的片段，为站内助手和外部智能体提供同一套依据。

#### 前置依赖
依赖阶段一的知识范围/授权和阶段二的就绪索引。检索服务独立于聊天页面和生成模型，避免只能在编辑器内部使用。

#### 需要覆盖的工作
- 支持当前文档、指定知识库以及当前用户可用知识范围的检索；身份从可信认证上下文获取，客户端传入的 userId/公司 ID 不能直接作为授权依据。
- 在关键词和向量召回时施加公司、集合与可见文档约束；取回正文/返回结果前，再对业务库中的当前权限、发布状态和版本进行校验。
- 定义关键词/语义召回、合并、去重和排序策略；先建立简单可评测的基线，再依据资料特点决定是否引入重排序模型。
- 处理多个集合中的重复文档、相邻片段、长文档与术语/编号检索；限制候选数量、最终返回量及总文本预算，避免堆积大量低相关资料。
- 明确空知识库、低相关结果、冲突资料、部分文档更新中以及索引故障的行为；可以只使用其余有效来源，但需显式说明范围受限，不能把无结果解释成公司没有此事实。
- 定义结构化检索结果：检索请求标识、文档/集合、发布标识、revision、片段标识、标题、来源位置、授权后文本和相关信息。
- 提供授权后的来源读取和定位能力。索引定位指向不可变发布版本；查看最新文档时提示版本差异；历史发布后来被撤回或用户撤权时不继续返回原片段。
- 缓存按身份/授权范围与发布状态隔离，明确失效规则；禁止因共享问题缓存而跨用户泄漏资料。
- 建立真实业务样例与期望来源的评测集，覆盖中文换说法、精确术语、跨文档问题、无依据和资料冲突；给出召回/排序/延迟等基线及后续阶段准入目标。

- 每个返回片段可定位到实际发布正文；无依据和服务故障具有不同结果状态。

### 知识平台阶段四｜上线站内知识智能助手与带来源的文档问答

### 知识平台阶段五｜开放统一知识服务 API 并接入外部业务系统

#### 阶段目标与用户价值

#### 需要覆盖的工作
- 提供两种版本化契约：检索服务返回授权知识片段/来源；问答服务返回基于资料的答案/引用/状态。调用方已有模型时可只使用检索服务。
- 请求声明允许的知识范围，响应带来源标识、发布版本、请求追踪信息和可理解的错误；明确更新中、资料不足、超时与配额等状态。

### 知识平台阶段六｜形成知识反馈、协同改进与公司试点运营闭环
