# CODI-194 工作台草稿清单的按需加载实测

在两个回环端口分别提供改前和改后的 Vite 生产构建。构建使用相同锁文件、构建标识与 API 代理，账号、文档库及后端进程相同。Chrome 每个宽度都开启全新的浏览器上下文，先加载登录页，真实登录后等到最近文档可见，再打开空白的本地草稿清单。统计浏览器 Resource Timing 返回的本机 JS/CSS，不计 API 请求、文档 HTML 与图片。采集 1280×850 和 320×850，两组数据一致。

| 取样阶段 | 改前资源数 / 编码字节 | 改后资源数 / 编码字节 |
| --- | ---: | ---: |
| 登录加工作台 | 31 / 376,642 | 28 / 355,809 |
| 登录后进入工作台的新增资源 | 19 / 101,790 | 16 / 80,946 |
| 首次点击草稿按钮的新增资源 | 0 / 0 | 6 / 23,466 |

进入工作台的解码正文由 290,472 字节减少到 230,088 字节，含协议开销的传输量由 107,490 字节降到 85,746 字节。Quill Delta 原先在工作台阶段获取，改后随草稿组件首次打开获取。登录并实际打开清单的总编码体积增加 2,633 字节，这组样本衡量资源体积而非首屏耗时。

实际生产脚本还在两档视口截留草稿代码资源，确认登录及工作台正常，打开时显示等待。返回 HTTP 503 后保留登录，焦点移到视口内的刷新按钮，刷新可重新请求并打开，Esc 返回原按钮。已有本机记录的恢复流程由真实 Chrome 的双账号协作端到端用例覆盖。
