# CODI-205 协作者添加确认复验

用真实 Chrome 从编辑器的「分享」进入协作者管理。改前，真实添加成功时只更新成员行，1280×850 和 320×640 的焦点都落到页面主体。改后，已确认的写入在表单下显示用户名和本次授予的角色，键盘焦点可到达提示。320px 提示完整位于弹窗内容的 y=344–412。

| 场景 | 实测结果 | 证据 |
| --- | --- | --- |
| 只读授权 | 两档真实写入，只读接收方在独立浏览器上下文打开原文档，正文 `aria-readonly=true`。确认后仍可键盘返回分享。 | [桌面改前](assets/codi205/before-1280.png) · [桌面改后](assets/codi205/final-read-1280.png) · [窄屏改前](assets/codi205/before-320.png) · [窄屏改后](assets/codi205/final-read-320.png) |
| 可编辑授权 | 两档键盘选择「可编辑」并提交。另一身份实际写入，等待已保存，再由所有者读取真实正文。 | [桌面](assets/codi205/final-edit-1280.png) · [窄屏](assets/codi205/final-edit-320.png) |
| 已写入、名单读取失败 | 真实写入确认后挂起名单请求，再返回 HTTP 503。写入确认和名单状态分别显示，重试读到真实成员。 | [窄屏读取中](assets/codi205/list-loading-320.png) · [窄屏读取失败](assets/codi205/list-failed-320.png) |
| 写响应丢失 | 在服务端实际提交后把浏览器响应替换为 HTTP 503。界面显示待核对，保留输入，刷新名单后查到只读成员。 | [窄屏](assets/codi205/unknown-320.png) |
| 未注册账号 | 真实请求返回业务 404 和「该用户名尚未注册」，不显示添加确认。 | [窄屏](assets/codi205/invalid-320.png) |

确认表示本次写入已经收到有效回复，最新权限仍以名单为准。未覆盖实体触屏、实际读屏、多管理员同时操作或其他浏览器。
