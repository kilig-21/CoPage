# 页面原身份与换号保护验收（2026-10-30）

本轮解决跨标签换号通知尚未到达时，旧页面及后来打开的弹窗借用新登录身份的问题。基线为 `efbe8cd91ac2316323c9bd63769e133c9ac84775`。这是一个局部闭环，完整产品交付、main/test 合并及公网发布仍单独判断。

## 真实复现

隔离来源文档26由合成账号3拥有，账号4有逐篇编辑权限。保留账号3页面的副本弹窗，在另一标签登录账号4；基线把副本27实际创建给账号4，创建收据也属于账号4。服务端按收到的账号4令牌处理，错误发生在前端意图与登录身份的绑定。副本27保留作对照。

另一个故障注入只延迟根组件的登录变化监听，其他 storage 监听正常送达。旧页面重新扫描副本待确认记录时，身份检查同步抛错，出现页面错误边界。证据为 `baseline-wrong-copy-verified.json`、`baseline-switch-render-error.json` 及对应 AX 文本。

## 实现

- 页面作用域捕获账号、令牌、服务；同页后来挂载的弹窗和控制器继承该身份。导航及登录生命周期重建作用域。
- 认证页面、弹窗和编辑器的常规 HTTP 请求在发送前核对原身份；成功或失败回复交回页面前再次核对。发送前失配不调用传输，迟到结果不交给新账号。
- 副本、项目内建篇、普通创建、导入、小组/项目创建和历史恢复在准备待确认记录前绑定原身份。待确认扫描通过 Promise 拒绝处理身份变化，避免同步错误冲出 React effect。
- WS 首次连接、重连、发送、接收均核对原身份。变化后先关闭通道，再收集未确认内容到原账号草稿；界面显示“登录已变化”，停止假装重连。
- 保存私人模板的控制器继承页面身份；登录页仍按自身的登录提交协议运行。
