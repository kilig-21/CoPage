# CODI-223 项目内文档筛选与键盘焦点

用 Chrome 在隔离环境打开同一合成项目。按 Enter 提交项目内筛选，暂缓项目详情 GET，截图后放行。在两档视口检查原输入元素是否仍在页面，以及它是否持有键盘焦点。

| 视口 | 加载时原输入框 | 返回空结果后键盘焦点 |
| --- | --- | --- |
| 1280×850 | 被卸载 → 保持可编辑 | BODY → 原输入框 |
| 320×640 | 被卸载 → 保持可编辑 | BODY → 原输入框 |

- 桌面加载 [改前](assets/codi223/before-loading-1280.png) · [改后](assets/codi223/after-loading-1280.png)
- 窄屏加载 [改前](assets/codi223/before-loading-320.png) · [改后](assets/codi223/after-loading-320.png) · [无匹配](assets/codi223/after-empty-320.png)

项目标题和筛选位置保持稳定，等待文字在筛选下方。等待期间只保留项目摘要，暂时隐藏旧文档操作并禁用项目写入。查询失败后可用原词重试，重试将焦点放回筛选输入。切换项目会清空原项目尚未提交的查询，收到访问失败后清理原项目摘要和文档。

生产构建 Chrome 7 项通过，覆盖两档宽度的键盘、慢请求时改词、503 重试、注入 403、空结果、跨项目切换，并复测项目列表、加入文档和从编辑器返回。前端 482 项、lint 和 Vite 构建通过。403 是浏览器内注入响应，本轮未变更实际小组成员权限，也未覆盖物理触屏、读屏器及其他浏览器。
