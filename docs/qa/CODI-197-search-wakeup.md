# CODI-197 正文保存到可搜索的实测

## 方法

在同一隔离预览中复用 Chrome、MySQL、Elasticsearch、合成账号和文档。基线运行 CODI-188 的 JAR，改后只替换后端 JAR。周期巡检保持 5000 ms。浏览器用键盘逐次追加唯一的正文词，记录发出的操作和对应的 WebSocket ACK。ACK 后每轮用同一个账号请求真实的 `/api/search`，未命中时等 125 ms 后继续，直到搜到该文档。改前和改后各 8 次，轮次之间使用相同的间隔序列。两组文档内容随追加增长，词的长度与结构相近。

| 观测值 | 改前 | 改后 |
| --- | ---: | ---: |
| ACK 至首次命中的中位数 | 3105 ms | 592 ms |
| ACK 至首次命中的最慢样本 | 5626 ms | 1165 ms |
| 8 次全部能搜到原文档 | 8 / 8 | 8 / 8 |

中位数下降约 81%。两组首次探测均未立即命中，索引仍异步。改后首个提交的发送至 ACK 用时 133 ms，当时后端刚启动。其余改后样本为 15–28 ms，改前为 12–20 ms。本试验用于比较检索可见时间。ACK 样本可查看，但样本数量和冷热条件不足以推断 ACK 性能变化。

## 正确性与界面

事务提交后只调度后台工作。250 ms 内的通知合并，同实例内的巡检和唤醒共用待处理游标并串行读写。失败的版本继续由 MySQL 保存为待处理。主动唤醒失败后有 5 秒退避，原有定时巡检仍会重试。Elasticsearch 外部版本和文档授权校验继续生效。

Chrome 1280px 和 320px 用键盘保存仅存在于正文的新词、搜索、打开命中项并返回。两档均检查空结果、加载和 HTTP 503 后重试。另一个无权限账号搜不到正文词。另以实际 MySQL 事务验证回滚不调度，并测试合并、调度拒绝、索引失败与定时补偿。未覆盖 32 篇以上同时产生待处理项的检索时效、生产网络或其他浏览器内核。
