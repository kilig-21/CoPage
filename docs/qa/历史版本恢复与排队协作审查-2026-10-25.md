## 分层差异与资源修正

最终算法先保留强前后缀和共享终止换行，再按段落、句子、词和滚动窗口寻找精确相同的共同块，用保序、不重叠的锚点划分区域。剩余区域每侧最多 64 码点作 Myers 双向对分，输出仍是原 UTF-16 Delta；图片按嵌入对象值匹配，属性独立求差异。长文本允许非全局最短差异；重复内容没有唯一的语义身份，不承诺任意重复文字的匹配位置都与人工选择相同。

共同文字上仅变化属性时继续 retain；目标正文自带显式 null 的旧格式，需要时只在对应目标格式片段作精确替换，并扩大到完整 Unicode 码点边界。**目标终止换行必须新建显式 null 属性时，现有 OT 无法同时表达精确格式与保留原换行身份，本次明确拒绝，原正文/历史/收据不变。** 原先已有同一 null 的换行可以正常保留；不删除该值或伪造恢复成功。该特殊存量兼容边界仍保留。

普通散列情况下，分层对齐成本为 `O((N+M)×64 + K log K)`，不会对全文高编辑距离作平方搜索。hash 命中仍核对真实内容；段边界偏移、跨 64 码点的共有区和重复长块的格式保留均有回归。算法的 bisect 部分改编自 [Google diff-match-patch](https://github.com/google/diff-match-patch/blob/master/java/src/name/fraser/neil/plaintext/diff_match_patch.java)，参考 [Quill Delta 的内容对齐与属性差异](https://github.com/slab/delta/blob/main/src/Delta.ts)；Apache 许可及修改归属进入 JAR 的 `META-INF`，没有新增依赖或修改依赖门槛。

两项必要资源修正同步完成：生成差异前先对 spans 规范化，避免小块全文改写反复拼接；应用差异时按相同格式缓冲文本后一次输出，保留格式、图片、null 和未覆盖尾部。独立复核又抓住“旧版大量格式碎片→目标单个 literal-null 段”仍被旧边界切碎的问题，改为从目标原始 run 建立独立迭代器。合法 24,000 个旧格式段（源 1,860,042 字节、目标 864,084 字节）修前算法调用累计分配约 15.07 GB，新增资源断言失败；修后约 58.86 MB、57 ms（累计分配不代表峰值堆占用），目标精确、共有前缀晚到格式与双向 OT 均通过。保留 `diff-null-run-before.log` 与 `diff-tests-null-run-final-512m.log`，不把中间 385 项版本当最终源码。

原 2 MiB 正文、4 MiB 单操作限制不变。生成规范化操作数使用严格 JSON 字节下界提前拒绝必然超限的极碎操作；恢复工厂使用持久化层原 mapper 精确核对字节，持久化事务仍再次核对。**合法大小正文不保证任意差异都可由一个 4 MiB 操作表达**：精确 2 MiB `abcd→abce` 极碎改写明确容量拒绝，零正文/热状态/收据/通知写入；不放宽门槛，也不退化成吞掉共同格式的整篇替换。

最终 53 项定向在 `-Xmx512m` 下 0 失败/错误/跳过；包含 2,000 组独立小 DP 对照、跨块/图片/emoji、双向 OT、UUID 重放、版本门禁、相同内容空恢复及容量/旧 null 拒绝。24K→25K 改写已成功；精确 2 MiB 大幅改写保留偏移的共同区、输出 5 条/2,094,217 字节操作。耗时只是该组合在本机的量测，不当作任意设备或任意正文的性能保证。
