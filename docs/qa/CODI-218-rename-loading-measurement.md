# CODI-218 重命名按需加载测量

从工作台打开同一篇「校园阅读节｜活动方案」，等待正文和保存状态可用。试验前和试验构建，各用 Chrome 新会话在 1280px 与 320px 分别跑三次。浏览器每次在打开文档前清除资源时间记录，比较随后 JS/CSS 请求的实际 `encodedBodySize` 总量。

| 测量项 | 基线 | 仅延后重命名 |
| --- | ---: | ---: |
| 进入编辑器的 JS/CSS 响应体 | 137,432 B | 137,303 B |
| 构建图中的原重命名资源或替代共享资源 | 17,392 B | 17,264 B |

同一构建的六次传输量一致。临时拆分把重命名表单移到独立动态模块，但编辑器仍下载承载共有依赖的 17,264 B 资源。实际首开收益为 129 B，约 0.094%。本地就绪耗时有波动，因此采用传输量判断。

撤回试验中的组件拆分。恢复后的 Vite 生产构建通过键盘创建和重命名两项 Chrome 回归。提交保留测量和选择依据，产品继续使用原重命名入口。
