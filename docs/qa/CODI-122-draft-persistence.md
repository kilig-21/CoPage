# CODI-122 大文档输入与草稿落盘验收

正文输入停止 400 毫秒后落盘，连续输入最多等待 2 秒。普通编辑不再为草稿逐键复制全文，只有真正落盘时才读出正文并序列化。工具栏按钮与保存状态仅在对应状态改变时更新。服务端确认最后一项修改后立即清理当前草稿槽。草稿继续沿用 v1 格式和原账号、文档、客户端标识。

协作断线、超时、撤权、切换身份、离开编辑页和 `beforeunload` 同步落盘。`pagehide` 可补偿未派发 `beforeunload` 的离页路径，隐藏标签时保存已经收集的修改。常规离页和撤权仍先收集正在进行的组合输入。存储拒绝写入时保留待写状态和原有复制备份提示。

## 输入对比

对比基线 `2d02953` 和同环境的候选生产构建。两个隔离文档由同一份 1,048,712 字节纯文本导入，使用相同浏览器环境和区域。临时页面保留真实连接、屏蔽测试文档的协作写入，确保 30 次输入均处于未确认状态。Chromium 实际插入 30 个字符，在不同主线程任务中记录每次输入处理时间，并统计该草稿槽的 `localStorage.setItem` 次数。

| 观察量 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 30 次输入的草稿写入 | 30 | 1 |
| 输入处理 P95 | 14.5 ms | 10.1 ms |
| 这批输入完成耗时 | 452 ms | 200 ms |
| 观察到的 50 ms 及以上长任务 | 0 | 0 |

## 恢复验收

在下列验证中将草稿计时延长至 20 秒以区分定时写入和同步兜底。测试前核对最后一段输入尚未落盘，功能数据使用隔离 Compose 的合成账号和文档。

| 情形 | 验证结果 |
| --- | --- |
| 浏览器进入离线 | `navigator.onLine` 为 false，编辑区暂停，最新正文和待确认操作已同步落盘 |
| 刷新 | 原浏览器立即重新打开，弹出恢复选项，正文和待确认操作可读 |
| 所有者撤销编辑成员权限 | 真实撤权请求及通知令协作者停止编辑，最新正文和待确认操作完整保留 |
| Chromium 关闭标签 | 关闭时实际出现 `beforeunload` 提示，重新开标签后正文、原操作和输入缓冲均保留。点击恢复并同步后，服务端确认全部编辑，浏览器清空该草稿槽 |
| 从编辑器返回文档列表 | 单页路由离开编辑器，草稿槽同步更新为最后输入 |
| 心跳超时 | 注入丢失 pong 并缩短等待，触发既有超时和重连路径，最新正文及待确认操作保留 |
