# 数据库结构迁移

后端启动时执行 Flyway。MySQL 8.4 空库从 V1 开始依次应用迁移。首次接管旧库时先检查核心表和列，登记版本 0，再补齐缺失的表和列。已有 Flyway 历史的库会对照已登记的脚本校验。Compose 初始化空卷时复用 V1，后端仍会核对并登记完整迁移历史。演示账号初始化独立于 Flyway。

首次接管已有库时，V1 对已存在的表会产生 MySQL 1050 提示。Spring Boot 管理的 Flyway 11.7.2 会对 MySQL 8.4 输出版本兼容性提示，CoPage 的迁移回归使用容器中的 MySQL 8.4.3。

原 `db/schema.sql` 作为旧 Compose 容器的挂载文件和迁移测试基准保留。后续结构变更只进入 Flyway 迁移目录。

## 修改数据库结构

1. 在 `backend/src/main/resources/db/migration` 新增递增的 `V<版本>__<说明>.sql`。已经发布的脚本必须保持原样，修正用后续版本。尽量让一个版本只含一个可独立核对的结构变更。
2. 在隔离 MySQL 8.4 实例测试空库和旧库副本，核对业务表、索引、约束、关键记录与 `flyway_schema_history`。迁移测试要求 `COPAGE_MIGRATION_TEST_MYSQL` 指向专用临时实例的 `主机:端口`，使用 `COPAGE_MIGRATION_TEST_PASSWORD` 连接测试实例的 root。执行 `mvn -f backend/pom.xml -Dtest=DatabaseMigrationTest test`。CI 会为该测试提供独立 MySQL。
3. 已有环境首次启用迁移前暂停写入，备份完整 MySQL（含已有迁移记录），并将备份恢复到另一个库。先在副本上迁移并核对记录数、正文及版本、权限及收据，确认成功后再安排目标库维护窗口。启动前再次确认 JDBC 目标与当前备份一致。恢复到新库时确保保留相同数据库字符集及排序规则。

## 旧格式与失败处理

V2～V4 添加的列使用 `ALGORITHM=INSTANT`。迁移连接的元数据锁等待上限为 10 秒。更早期的 `doc_operation.op` 可能还是 `TEXT`。修改该列类型需要复制表，因此应用会在写入迁移历史前中止。先在隔离副本评估表体积、额外磁盘空间、锁等待和实际耗时。应用暂停写入且备份已验证后，在维护窗按旧表的实际字符集和排序规则执行下面的扩容操作。

```sql
SET SESSION lock_wait_timeout = 10;
ALTER TABLE doc_operation MODIFY COLUMN op LONGTEXT NOT NULL, ALGORITHM=COPY;
```

MySQL 的 DDL 会隐式提交。某一版本失败后，启动失败会阻止应用对外服务，之前成功的 DDL 可能仍然存在。先核对 `flyway_schema_history`、实际表结构和备份，然后把故障在副本复现。应用配置禁用了 Flyway clean。修复和重试前须明确哪些语句已经落盘。

V5 以 `ALGORITHM=INSTANT` 添加搜索版本和待处理状态，V6 以 `ALGORITHM=INPLACE, LOCK=NONE` 构建索引。V6 仍需扫描现有数据并在开始和完成时取得元数据锁。升级前先在副本确认索引构建的耗时和磁盘空间，安排暂停旧版本写入并一起升级各后端实例。

## 恢复到迁移前

保留故障库及日志。将迁移前完整备份恢复到另一空库，使用原应用版本与恢复库验证账号、文档、权限、版本和收据，再把应用连接指向已核对的恢复库。V2～V4 为新增字段，原版本在对应的迁移副本中应可读取原有数据，但切回原版时仍先在副本验证。遇到已经接收迁移后写入的情况，保留两个数据集，确认新增写入的补回方案后再切换。

下面的 PowerShell 命令假定已配置 `copage-source` 和 `copage-restore` 两个 MySQL 客户端登录路径，恢复库已单独创建且数据库名不同于源库。先生成迁移前备份，恢复时使用保留下来的同一文件。

```powershell
mysqldump --login-path=copage-source --single-transaction --skip-add-drop-table --no-tablespaces --result-file=copage-before-migration.sql collab_doc
if ($LASTEXITCODE -ne 0) { throw '备份失败' }

$tables = mysql --login-path=copage-restore --batch --skip-column-names --database=copage_restore --execute='SHOW TABLES'
if ($LASTEXITCODE -ne 0 -or $tables) { throw '恢复库必须可连接且为空' }
mysql --login-path=copage-restore --default-character-set=utf8mb4 --database=copage_restore --execute='SOURCE copage-before-migration.sql'
if ($LASTEXITCODE -ne 0) { throw '恢复失败，继续保留源库和备份' }
```
