## 提交和复盘规则

1. 按表格顺序推进；较后阶段已有的未提交代码保留在工作树中，先用于修复当前构建，不提前声称对应任务已完成。
2. 一个提交只包含本闭环涉及的文件。提交前运行相关测试或构建，并记录无法验证的环境条件。
3. 每阶段复盘协议、数据一致性、权限边界和演示路径；发现问题先修再进入下一阶段。
4. `test` 用于集成，`main` 用于最终交付；当前在 `feat/collab-core`。合并前重新核对其他分支和未提交改动。
