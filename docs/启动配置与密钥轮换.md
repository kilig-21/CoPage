# CoPage 启动配置与密钥轮换

启动守卫在 Spring 初始化期间读取实际生效的配置，先于数据库迁移和连接。默认 `COPAGE_CONFIG_MODE=strict`。校验失败会退出并指明配置项，日志仅包含配置名与规则。

| 模式 | 使用范围 | 传输 |
| --- | --- | --- |
| `strict` | 应用及依赖跨主机运行 | 前端 origin、图片公开地址、Elasticsearch 和 MinIO 使用 HTTPS。MySQL 使用 `sslMode=VERIFY_IDENTITY`，Redis 和 RabbitMQ 启用 TLS。 |
| `private-compose` | 仓库的单机生产 Compose | `mysql`、`redis`、`rabbitmq`、`elasticsearch` 和 `minio` 仅在同主机 Compose 网络内可以使用明文传输。前端和图片公开地址仍需 HTTPS。 |
| `local` | 回环或本地演示 Compose | 前端及图片公开地址必须是回环地址，依赖限回环或项目的本地 Compose 服务名。使用 `prod` profile 时要求前两种模式之一。 |

`private-compose` 的 MySQL URL 显式设置 `sslMode=DISABLED`，等效于原配置的 `useSSL=false`。将依赖移出该网络时使用 TLS。配置 MySQL CA 时可使用 JVM 信任库。[Connector/J TLS 参数](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-security.html)

生产模式要求独立 MySQL 和 RabbitMQ 应用账号、Redis 密码、MinIO 账号和密码。JWT 最少 32 字节，服务密码最少 12 字节，MinIO 账号最少 8 字节。取值应使用随机生成的独立凭据。单项替代连接 URL 可能覆盖校验所使用的字段，本项目使用单机 Redis、RabbitMQ 的独立主机与密码配置，Flyway 共用应用数据源。[Spring Boot 连接属性](https://docs.spring.io/spring-boot/3.5/appendix/application-properties/)

Windows 一键启动在未配置 `JWT_SECRET` 时为本地进程生成随机密钥。这种启动方式会在后端重启后要求重新登录。手动启动本地后端时，先向终端传入 `COPAGE_CONFIG_MODE=local` 和随机 `JWT_SECRET`。启动可选的 `app` 容器时，随机 `JWT_SECRET` 通过启动 shell 或本机未跟踪的 `.env` 传入。共同开发的本地实例需要通过同一安全渠道配置相同的 JWT 密钥。仓库的环境文件示例保留空项。

## JWT 轮换

1. 安排维护窗口，通知在线用户确认编辑器已保存或下载未确认草稿。用可信随机源生成至少 32 字节的新密钥，保存到现用密钥管理渠道。记录旧版本标识和回退条件。
2. 将所有后端实例移出代理入口并停止，使保存中的请求有机会在停止宽限期内完成，现有 WebSocket 随进程关闭。生产 Compose 命令为 `docker compose --env-file .env.production -f compose.production.yml stop backend`。
3. 在所有实例更新同一个 `PROD_JWT_SECRET`（直接启动时为 `JWT_SECRET`）。用 `docker compose --env-file .env.production -f compose.production.yml up -d --no-deps --force-recreate backend` 重建后端，保持数据服务和数据卷在线。
4. 等待所有实例的 `/actuator/health/readiness` 返回 HTTP 200。用轮换前的合成会话调用受保护的接口，应返回 401，重新登录后应返回 200，并能建立新的协作连接。恢复代理入口，请用户重新登录。
5. 如果需要回退镜像，优先保留新密钥。只有旧密钥仍可信、且能接受仍在有效期内的旧会话可能恢复，才按同一停机步骤恢复旧版本密钥。发现旧密钥泄露时使用新的健康构建或生成另一枚全新密钥。

轮换会让所有原有 JWT 失效。已提交文档仍在 MySQL，未确认草稿按原账号保留在浏览器。维护期间使用单次切换，避免同一个会话被配置不同密钥的实例交替接收。

## 依赖凭据轮换

在维护窗口逐项处理，并先核对备份。各项切换后恢复后端，检查 readiness 及相应功能，再继续下一项。

- **MySQL**　停后端。通过有权限的管理连接更新数据库内 `copage` 账号密码，再同步 `PROD_MYSQL_PASSWORD`，重建后端检查迁移和读写。若轮换 root，更新实际 MySQL 账号并同步 `PROD_MYSQL_ROOT_PASSWORD`，重建 MySQL 容器让健康探针读取新配置。现有数据卷的账号由数据库管理命令修改，容器环境变量只负责初始创建与客户端配置。
- **Redis**　停后端。更新 `PROD_REDIS_PASSWORD`，使用 `up -d --no-deps --force-recreate redis` 让 Redis 从既有 AOF 卷和新凭据启动。确认健康后重建后端并验登录与协同。
- **RabbitMQ**　停后端。在 broker 内修改现有应用用户的密码，再同步 `PROD_RABBITMQ_PASSWORD` 并重建后端。确认消息消费与索引更新。容器默认用户变量用于新节点初始化。
- **MinIO**　停后端。同步更新 `PROD_MINIO_ROOT_USER` 与 `PROD_MINIO_ROOT_PASSWORD`，按顺序重建 `minio`、`minio-init` 和 `backend`，等待初始化容器退出码 0 后启动后端。确认存量图片可读以及新图片可上传。

需要回退时，服务端凭据和后端配置同时回到上一可信版本。复核健康探针后，再恢复对外入口。命令输出、环境文件和密钥通过受控渠道保存。
