# CoPage 交付验收清单（CODI-92）

本清单用于课程演示前的**重新验收**，不是“功能已全部完成”的声明。架构与协议以 [README](../README.md)、[接口约定](接口约定.md) 和实际代码为准；每次演示前记录日期、分支、提交号及失败项，不沿用旧的通过结果。

## 1. 环境与自动化回归

在项目根目录用 PowerShell 执行。JDK 21、Maven 3.9+、Node.js 20+ 与 Docker Compose v2 的安装及本地端口见 README。

```powershell
git status --short --branch
git rev-parse --short HEAD
docker compose up -d
docker compose ps -a
mvn -f backend/pom.xml test
npm --prefix frontend test
npm --prefix frontend run build
```

判定：MySQL、Redis、RabbitMQ、Elasticsearch 为 `healthy`；MinIO 正在运行，`minio-init` 成功退出（状态码 0）；三项测试/构建命令均以状态码 0 结束。记录实际测试数和构建警告，不把旧记录当作本次结果。`docker compose up -d` 使用**本地开发凭据和公开宿主机端口**，不可直接作为公网部署配置。

## 2. 后端双实例协同验收

在两个独立终端分别启动 `8080` 和 `8081`；终端保持运行。启动命令和 IDEA 方法见 README。随后在第三个终端执行：

```powershell
$env:COPAGE_SMOKE_PORT_A = '8080'
$env:COPAGE_SMOKE_PORT_B = '8081'
node scripts/collab-smoke.mjs
```

此脚本使用本地演示账号，在共享基础服务上创建一个测试文档，验证跨实例广播、已提交/未提交操作的断线追赶、opId 去重和 30 个并发客户端的确认；结束时软删除测试文档。失败时先保留终端输出和两实例日志，再检查依赖、端口、账号与配置，不直接重跑到“碰巧通过”。如要验收容器实例，把 A 设为 `8082`、B 保持 `8081`，先按 README 启动可选的 `app` profile；这只证明本地容器互通，不证明公网部署。

## 3. 人工浏览器演示（由演示者最终确认）

1. 启动前端 `npm --prefix frontend run dev`，在 `http://localhost:5173` 登录、新建文档；另开标签页访问同一文档。两页都显示“已连接”后轮流输入，检查文字和 revision 收敛。不同账号参与前，应先确认其协作者权限；知道链接不等于有编辑权。
2. 刷新一页，确认正文仍在；使用只读协作者或无权限账号分别检查不能编辑、不能访问。演示错误账号登录与无 token 请求被拒绝。
3. 在**事先确认可中断的本地测试实例**上演示断线：停止其中一个后端时，连接到该实例的页面应显示重连并暂时只读；恢复同一实例后应重新同步并可继续编辑。不要在有他人使用的服务上执行此步骤。
4. 若出现未确认草稿，刷新/重开后应先显示恢复确认，而非自动重发；确认前后分别检查服务端版本，防止重复提交。历史缺口超过 2000 条时，当前实现保留本地内容并转只读，需要人工复制备份，**不演示为自动无损恢复**。
5. 搜索页面与协作者管理入口仍未完成。图片按钮已接入上传接口；本地浏览器已验证文件选择、图片 URL 可访问、保存后刷新保留。另在两个先连接的标签页通过编辑区粘贴图片验证实时图片 Delta 广播；按钮上传与实时广播**尚未在同一次操作中联合验证**。远程彩色光标与名字标签须验证两端位置、失焦/离开隐藏、断线恢复及并发编辑后的移动。未测前不能宣称界面闭环。

图片接口单独烟测命令为 `node scripts/image-upload-smoke.mjs`，默认检查本机 8082 容器实例；它不覆盖本节的浏览器步骤，并会留下一张需按输出 URL 清理的 64×64 测试图。

演示记录至少包含：日期、提交号、测试环境、每一步的通过/失败、服务端最终正文和 revision，以及失败时的复现步骤。截图或日志需删除 JWT、密码、个人资料和本机私有地址后再对外分享。
